# 运行日志

状态：服务端使用统一的结构化运行日志，供本机或部署环境排查服务状态；日志不参与 Agent 执行，也不是会话、消息或任务状态的事实来源。

## 位置与查看

- 服务运行事件同时输出到后端终端，并按 UTC 日期写入 `PIKO_HOME/logs/piko-YYYY-MM-DD.jsonl`；默认目录为 `~/.piko/logs/`。
- 每行是一条 JSON 记录，包含 UTC `timestamp`、`level` 和稳定的 `event` 名称，以及少量事件字段。
- 启动时清理超过 14 天的 Piko 日志文件；清理只针对符合命名规则的普通文件。日志目录不可用时，服务继续运行并退回终端输出。
- 开发时可直接观察 API 终端；也可跟随文件：

  ```bash
  tail -f ~/.piko/logs/piko-$(date -u +%F).jsonl
  ```

  Windows PowerShell：

  ```powershell
  Get-Content "$HOME\.piko\logs\piko-*.jsonl" -Wait
  ```

## 记录范围

- 服务启动、关闭、启动恢复和资源初始化失败。
- 有副作用的 API 请求摘要和失败请求；不记录成功读取请求或 SSE 事件连接。
- 会话输入接纳/结算、运行开始/结束、工具名称/状态/耗时和压缩生命周期。
- 任务命令与定时执行接纳、旁聊管理、Telegram 轮询和投递错误。

## 隐私边界

- 不记录用户/助手消息、提示词、模型回复、工具参数或结果、附件内容、会话标题、Telegram 用户/聊天 ID、凭据或完整错误堆栈。
- HTTP 日志不包含查询参数；旁聊和任务路径中的实体 ID 会归一化。错误只记录类型、错误码或状态码，不记录错误消息。
- 日志仍包含时间、HTTP 路由、Durable 会话/任务 ID、工具名称等运行元数据。应按本机运维数据保护，不要公开日志文件。
- 文件不写入 Durable SQLite，也不通过 API 或 App 暴露；当前不提供日志级别配置、下载或界面查看。
