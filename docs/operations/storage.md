# Durable SQLite 存储

Piko 使用 Durable 原生 SQLite 保存会话、消息、提交、任务和文档；不另存第二份消息正文或执行状态。

## 存储位置与边界

数据库位于 `PIKO_HOME/state/durable/session.sqlite`，默认 PIKO_HOME 为 `~/.piko`。SQLite 使用 WAL，运行时可能同时有 `-wal` 和 `-shm`；一个状态目录只允许一个后端写进程。损坏、不支持的格式或非空目录缺少数据库时拒绝启动，不静默创建空会话。日志独立于数据库，见[运行日志](logging.md)。

## 备份与恢复

1. 停止后端并确认没有其他进程使用同一状态目录。
2. 备份整个 PIKO_HOME，以及单独指定的工作区；SQLite 目录连同 WAL/SHM 成套保存。
3. 恢复时使用原工作区绝对路径。定期验证备份，并按敏感数据保护；应用内删除不会清除备份。

## 删除与隐私边界

旁聊删除覆盖所属后台工作；保存任务删除覆盖历次执行及专属目录；帖子删除覆盖正文和专属生成过程。主会话已收到的报告不随后台执行回收。旁聊和帖子删除不删除附件、工作区文件、产物、备份或供应商侧记录，也不回滚外部副作用。具体见[旁聊](../features/side-chats.md#永久删除边界)、[任务](../features/tasks.md#持久化与目录)和[帖子](../features/posts.md#删除)。

SQLite 清理不能保证擦除文件系统快照、SSD 历史块、复制件或备份；不要将应用内删除描述为全介质安全擦除。

## 临时执行的保留期

无长期业务归属的临时工作保留 7 天，每 24 小时检查；运行中、等待报告或仍有活动依赖的执行跳过。旁聊、保存任务和已发布帖子的专属过程随所属对象保留。回收不删除主会话历史、记忆或产物；SQLite 文件不保证立即变小。

## 共用删除协议

删除按业务归属计划和复核，使用 Durable 原生提交线退休并清理状态；未完成清理在恢复调度前继续。业务层负责自身的删除意图与目录收尾，不能并行绕过 Harness 修改活跃状态。删除失败不报告成功。

隔离环境已检查归属删除、保留期和中断恢复；实际备份恢复仍应在部署环境验证。
