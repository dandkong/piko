# 数据与备份

[English](storage.md) | 中文

Piko 默认把配置、状态和工作区放在 `~/.piko`。`PIKO_HOME` 可指定其他绝对路径，`PIKO_WORKSPACE` 可另行指定绝对工作区。已有会话记录工作目录；更换路径不是自动迁移。

- `config/` 包含私有配置和凭据。
- `state/durable/session.sqlite` 是 Durable 数据库；SQLite 使用 WAL，可能同时存在 `-wal` 和 `-shm` 文件。
- `state/attachments/` 统一存放接收附件和助手发送文件的独立快照，不自动清理。
- `state/tmp/` 存放运行时临时文件，每次后端启动时清空，不应放置长期文件。
- `workspace/` 默认保存助手指导、记忆、技能和产物。

## 备份与恢复

1. 停止后端，确认没有其他进程使用同一 `PIKO_HOME`。
2. 完整复制私有 home（含 SQLite 目录及可能存在的 WAL/SHM）和单独配置的工作区。备份可能包含凭据、会话、工具数据和路径，须妥善保护。
3. 启动前将完整备份恢复到兼容部署和原工作区绝对路径；已有会话路径不匹配时会拒绝启动。不要让两个后端使用同一状态目录，并定期验证备份可恢复。

数据库损坏、不支持的旧格式或非空目录缺少预期数据库时，后端会拒绝启动，不静默创建空会话。当前没有旧格式导入工具；升级前备份整个 home，新版本写入的数据不保证能被旧版本读取。详见[存储说明](../operations/storage.md)。

## 删除与保留

删除旁聊会清理其所属后台工作；删除保存任务会清理执行记录和专属任务目录；删除帖子会清理其专属生成记录。旁聊和帖子删除不删除附件、工作区文件、产物或备份；删除也不回滚外部副作用或清除供应商侧记录。

没有长期业务归属的临时后台执行每 24 小时检查，最后活动满 7 天后回收；运行中或有未消费输入/报告时跳过。此策略不删除主会话历史、记忆文件或工作区产物。附件不自动删除；手动删除文件会使对应历史附件失效。运行时临时目录在后端启动时清空。

删除应用数据不会删除独立备份或文件系统快照。Piko 工作区是工作目录，不是沙箱。
