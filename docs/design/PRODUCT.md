# Piko 产品约定

Piko 是本地优先的个人助理，通过持续对话帮助用户思考、规划和开展工作，并保存记忆与有用的成果。实际执行、数据和工作区位于后端机器；Web、原生客户端和可选 Telegram 提供访问入口。

## 产品结构

- **Chat**：默认进入持久主会话，作为与助手持续沟通的入口。旁聊有独立历史和上下文，共享工作区资源；不自动继承或回传主会话内容。参见[主会话](../features/main-chat.md)和[旁聊](../features/side-chats.md)。
- **Tasks**：通过对话保存可手动或定时运行的任务，在页面查看已结束的执行记录并管理任务生命周期。参见[任务与执行记录](../features/tasks.md)。
- **Posts**：助手根据用户上下文自动或手动生成的私人阅读内容。参见[个性化帖子](../features/posts.md)。
- **Artifacts**：浏览助手保存的正式成果。参见[产物浏览](../features/artifacts.md)。

一级导航保持这四项，不用模拟内容填充空状态。用户用对话交办工作；专门页面负责查看和管理真实存在的任务、帖子与成果。

## 工作与结果

- **后台工作**是直接委派给助手的工作，可以继续补充；结果只回到发起它的会话。用户不必理解子 Agent 的技术结构。参见[后台工作](../features/background-subagents.md)。
- **任务**是保存下来的工作指令，不是待办勾选项；一次运行产生一条**执行记录／运行结果**。归档停止未来调度并保留历史，不等于某次执行完成；恢复不立即运行。
- **工作区**主要供助手保存指导、记忆、技能和工作材料。任务目录属于助手的内部工作空间，不自动成为面向用户的产物；用户需要交付文件时，助手可将正式成果放入 `artifacts/`。
- 助手应依据实际工具结果说明完成与否，不把计划或未验证的操作当作已完成。

## 通道与边界

主会话由 App 和可选 Telegram 共用；各通道遵循自身平台能力，不要求界面功能完全一致。旁聊的上下文、后台工作和结果限定在发起会话。参见[双通道说明](../features/telegram-channel.md)。

Piko 使用单用户访问密钥登录，不提供多用户隔离、细粒度权限或文件沙箱；文件、命令和外部工具可能产生真实副作用。工作区不是安全边界，面向不可信网络的访问需要额外保护。具体实现和限制见[架构约定](ARCHITECTURE.md)及[功能文档](../README.md#功能说明)。

视觉与控件的一致性遵循[交互与视觉规范](INTERACTION.md)；功能特定的交互、状态和限制保存在对应功能文档。
