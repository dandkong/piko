# 交互与视觉规范

Piko 客户端的统一交互基线。新增或修改任何可交互控件时应先复用本文档的规则与组件；例外需要说明原因，并同步更新本文档。

当前状态：基础层与抽屉、顶栏、底部导航、聊天输入区、任务页主要操作已按此规范接入。具体覆盖范围见文末。

## 1. 目标

- **轻**：不使用水波纹、弹跳或强对比闪烁；按压只做轻微缩放和背景变化。
- **稳**：同类动作的尺寸、圆角、颜色、反馈和动效保持一致。
- **可预期**：默认、悬停、按压、焦点、选中、禁用、加载都有明确表现。
- **可用**：所有图标按钮的有效命中区域不小于 44×44；键盘和读屏用户能获得与指针用户相同的信息。

## 2. 交互层级

| 层级 | 用途 | 默认表现 | 示例 |
| --- | --- | --- | --- |
| Primary | 提交、创建等主操作 | 浅蓝底 `#C8E7FF` | 发送、新建旁聊 |
| Secondary | 普通动作 | 白底细边框或浅灰底 | 菜单、设置、关闭、返回、回到底部 |
| Tertiary | 列表行、标签、附件 | 透明或浅灰，交互时给背景 | 抽屉页签、任务行、附件 chip |

规则：

- 同一区域只放一个 Primary 操作。
- 导航选中状态使用浅灰；浅蓝只表达“提交/创建”，不用于选中。
- 设置是 Secondary；新建旁聊在实现后是抽屉内唯一的 Primary。
- 未实现的功能必须明确置灰，不能看起来可点却没有任何反馈。

## 4. 尺寸与圆角

| 项目 | 规范 |
| --- | --- |
| 图标按钮（md） | 44×44 |
| 图标按钮（sm） | 36×36，配合 8px hitSlop 达到至少 44 |
| 行按钮 | 最小高度 48 |
| 文本按钮 | 高 36，水平内边距 12 |
| chip | 高约 32，半径 12 |
| 最小命中区域 | 44×44 |
| chip 圆角 | 12 |
| 控件圆角 | 16 |
| 卡片圆角 | 18 |
| 面板圆角 | 30 |
| 圆形按钮 | 50% |

图标统一使用 lucide，默认描边 1.8：

- 导航图标：22
- 动作图标：20–22
- 关闭等辅助图标：18

## 5. 动效

| 场景 | 时长 | 曲线 |
| --- | --- | --- |
| 按下 | 90ms | cubic-out |
| 松开 | 160ms | cubic-out |
| 悬停 / 状态色 | 即时切换 | — |
| 主界面推开 / 归位（仅横向平移） | 260ms / 200ms | cubic-out |

- 按压缩放：图标按钮 0.94，Primary 0.95，底部导航图标 0.92，chip 0.98；整行不缩放。
- 系统启用“减少动效”时，所有位移与缩放时长为 0。抽屉仅平移主界面，不对大型聊天表面动画缩放、阴影或圆角裁切。
- 不使用循环呼吸、按压回弹或跨页面共享元素动画来表达普通按钮。

## 6. 状态矩阵

| 控件 | 默认 | 悬停（Web） | 按压 | 焦点（键盘） | 选中 | 禁用 |
| --- | --- | --- | --- | --- | --- | --- |
| 图标按钮 Secondary | 白底细边框 | `#F8F9FA` | 缩放 + `#ECEEEF` | 2px 焦点环 | — | 40% 透明度，无反馈 |
| 图标按钮 Primary | `#C8E7FF` | `#BCE0FC` | 缩放 + `#AED7F7` | 2px 焦点环 | — | 退回浅灰底，40% 透明度 |
| 行 / 抽屉页签 | 透明 | `#F8F9FA` | `#ECEEEF` | 2px 焦点环 | `#F0F1F2` | 40% 透明度 |
| chip | `#F3F5F6` | `#EDF0F2` | 缩放 + `#E6EAEC` | 2px 焦点环 | — | 40% 透明度 |
| 文本按钮 | 浅灰或透明 | 背景加深 | 缩放 0.97 | 2px 焦点环 | — | 40% 透明度 |

焦点环只在键盘聚焦时出现；鼠标点击不显示焦点环。

## 7. 组件与代码位置

| 组件 | 位置 | 说明 |
| --- | --- | --- |
| `TactilePressable` | `apps/mobile/src/components/TactilePressable.tsx` | 统一处理悬停、按压、焦点、选中、禁用和缩放 |
| `IconButton` | `apps/mobile/src/components/IconButton.tsx` | 图标按钮，支持 `card` / `soft` / `plain` / `primary` 和 `sm` / `md` |
| `TextButton` | `apps/mobile/src/components/TextButton.tsx` | 文本动作，统一内边距、按压和焦点 |
| `TextInputDialog` / `TextInputDialogContent` | `apps/mobile/src/components/TextInputDialog.tsx` | 通用受控单行文本弹窗；已有 Modal 的菜单切换复用 Content，不叠加原生 Modal |
| 令牌 | `apps/mobile/src/theme.ts` | `radii`、`controlSizes`、`motion`、`stateColors` |

使用约定：

- 图标按钮优先用 `IconButton`，不要直接写 `Pressable` 圆角样式。
- 整行可点用 `TactilePressable` + `variant="plain"`，`scaleTo={1}`，不要在行上做缩放。
- 列表行、附件 chip 的交互背景由 `TactilePressable` 的 variant / state 控制；自定义 `faceStyle` 不要设置 `backgroundColor`，否则会覆盖悬停、按压和选中色。
- 底部导航与抽屉页签使用同一套浅灰选中背景；悬停、按压和选中只保留一层状态背景。
- 主操作只在真正可提交时使用 `primary`；不可用时退回 `soft` 并置灰。
- 重命名等单行文本输入复用 `TextInputDialog`，不在列表原地展开输入框。调用方预填当前值、提供保存回调；弹窗统一取消/确认、空白禁用、保存中锁定、错误提示、键盘避让和 Escape 取消。保存成功才关闭，失败保留输入；Enter 可确认。菜单切换输入时复用同一个 Modal 与 `TextInputDialogContent`，避免 iOS 连续呈现两个原生弹窗。
- 新增颜色、尺寸或动效前先检查 `theme.ts` 是否已有可用令牌。

## 8. Web 与原生

- Web：支持 hover、键盘 focus-visible、Escape 关闭浮层；点击按钮不显示焦点环。
- 原生：使用按下缩放和背景变化，不使用 Android 水波纹；系统返回键行为保持不变。
- 头像下方实时活动共用各端现有状态栏：整轮开始显示“思考中…”，工具开始或正文输出更新为 3–5 字标签或“正在回复”，无中文映射的工具统一显示“调用工具”。标签保留到下一活动覆盖，整轮结束后清空，不因工具/单条回复完成而回退。活动由服务端投影，加载、上传、停止和重连状态仍优先；不替换聊天气泡里的等待动画、不新增工具气泡。
- 所有平台共享同一套尺寸和状态，不为平台单独发明按钮样式。
- 主聊和旁聊共用滚动规则：只挂载当前可见聊天的列表，切走卸载；刷新、首次进入和切回会话都从最新位置开始，不恢复旧阅读位置。初始跟随持续覆盖历史加载、顶栏状态和输入区尺寸就绪，会话数据、草稿、附件和请求身份仍按会话保留。
- “是否贴底”和“是否跟随”独立：离底超过 2 个布局单位才显示“最新消息”箭头；发送本地新消息或点击箭头恢复跟随，手动滚回底部同样恢复。用户拖动、上滚或键盘翻页解除跟随；历史快照、等待提示、正文增长与布局变化本身不能解除或重新抢回跟随。处于阅读位置时，恢复观察的 busy 快照不触发置底。
- Web 按真实滚动容器的尺寸同步置底，监听包含 padding 的完整内容与视口尺寸；自动跟随和点击箭头都直接定位，不启动会保留旧目标的浏览器平滑滚动。箭头依据实际位置隐藏，不用点击或发送状态假装已到达。加载更早历史保留可见消息的位置。原生使用列表尺寸/滚动事件，用户拖动时不自动校正。聊天输入区与底部导航仍共用一份实测高度，供列表留白、渐隐和按钮定位使用。
- App 助手消息使用 markdown-it-cjk-friendly 处理中日韩文字与标点相邻时的 Markdown 边界，使用 remend 补全流式显示；不改消息原文。流式更新保持同结构 Markdown 节点与气泡的展示身份，提交为正式条目不重挂载整条回复；语法补全引起的真实排版变化仍可能改变高度。Web 导出可用，原生设备上的实际显示仍需真机核验；Telegram 使用独立的富文本渲染链路。
- 旁聊删除必须先显示确认弹窗，说明不可恢复及不清理附件、工作区文件和历史备份。取消不发送 DELETE，提交期间禁用重复点击和关闭，失败保留确认框与重试；删除当前旁聊返回主会话。在线 deleted 通知或旧旁聊 404 会清空对应客户端状态并停止重连，不能把“断线重试”用于复活已删除会话。
- 聊天输入区与底部导航是共用容器，其实测高度只保存一份，供消息列表留白、底部渐隐和“最新消息”按钮共用，不按会话缓存；切换会话但容器尺寸不变时，不能依赖新的 onLayout 通知补高度。
- 触屏命中区域不足 44×44 时，用 `hitSlop` 扩大，不改变视觉尺寸。

## 9. 可访问性

- 所有按钮必须有 `accessibilityLabel`；图标按钮不能只靠图形表意。
- 状态通过 `accessibilityState` 暴露：`disabled`、`selected`、`expanded`、`busy`。
- 键盘 Enter/Space 应能触发；焦点顺序与视觉顺序一致。
- 抽屉：底层全高铺到主界面左侧，以略深冷灰背景和 1px 细分界线表达层级，不做悬浮卡片边距、圆角或阴影；宽度为屏幕的 76%，最多 300。主界面只作为前景右移，不缩放、不重排内容；抽屉标题不放关闭叉号；可点击露出的前景表面、按 Escape 或 Android 返回关闭。菜单打开时主界面对读屏隐藏，焦点留在抽屉。旁聊三点菜单的图标与文字整体左对齐。
- 禁用控件仍保留在可访问性树中，并向读屏说明当前不可用。

## 10. 修改规则

1. 新按钮先选层级，再选组件，最后才写局部样式。
2. 同一页面出现第二个 Primary 时，先确认是否真的需要。
3. 新增状态（例如 loading、danger、toggle）时，先补充本文档和令牌，再落代码。
4. 交互改动需要在 Web 和至少一个原生目标上验证；未验证的范围在文档中注明。
5. 本文档与 `docs/PRODUCT.md` 冲突时，以产品行为为准，并同步修正本文档。
