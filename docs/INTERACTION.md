# 交互与视觉规范

Piko 客户端的统一交互基线。新增或修改任何可交互控件时应先复用本文档的规则与组件；例外需要说明原因，并同步更新本文档。

当前基线：克制中性、适配浅色与深色。默认跟随设备外观，也可在设置中固定深色或浅色；配色、圆角和状态由 `apps/mobile/src/theme.ts` 提供，组件通过主题上下文响应切换；常用控件复用共享交互组件。具体覆盖范围和平台验证边界见文末。

## 1. 目标

- **轻**：不使用水波纹、弹跳或强对比闪烁；按压只做轻微缩放和背景变化。
- **稳**：同类动作的尺寸、圆角、颜色、反馈和动效保持一致。
- **可预期**：默认、悬停、按压、焦点、选中、禁用、加载都有明确表现。
- **可用**：所有图标按钮的有效命中区域不小于 44×44；键盘和读屏用户能获得与指针用户相同的信息。
- **克制**：中性灰承载导航、列表和焦点状态；浅蓝突出主提交动作，并区分自己发送的聊天消息，不给普通行、选中项或输入焦点染色。

## 2. 交互层级

| 层级 | 用途 | 默认表现 | 示例 |
| --- | --- | --- | --- |
| Primary | 提交、创建等主操作 | 浅色浅蓝底 `#D6EEFF`；深色暗蓝底 `#19394D` | 发送、新建旁聊 |
| Secondary | 普通动作 | 当前主题的卡片底、细边框或中性灰底 | 菜单、设置、关闭、返回、回到底部 |
| Tertiary | 列表行、标签、附件 | 透明或当前主题的中性灰底，交互时给背景 | 抽屉页签、任务行、附件 chip |

规则：

- 同一区域只放一个 Primary 操作。
- 导航和列表选中使用当前主题的中性灰；蓝色用于“提交/创建”主操作和自己发送的聊天消息，不用于列表选中或普通控件的 hover、按压。
- 深蓝用于链接和待保存等信息状态；其他控件的焦点反馈使用当前主题的 `focus` 色。
- 设置是 Secondary；新建旁聊是抽屉内唯一的 Primary。
- 未实现的功能必须明确置灰，不能看起来可点却没有任何反馈。

## 4. 尺寸与圆角

| 项目 | 规范 |
| --- | --- |
| 图标按钮（md） | 44×44 |
| 图标按钮（sm） | 36×36，配合 8px hitSlop 达到至少 44 |
| 行按钮 | 最小高度 48 |
| 文本按钮 | 高 36，水平内边距 12 |
| chip | 高约 32，半径 12 |
| 文本输入 | 高至少 48 |
| 最小命中区域 | 44×44 |
| 控件、chip、错误提示圆角 | 12 |
| 卡片、弹窗、消息气泡圆角 | 18 |
| 浮层面板、聊天输入区圆角 | 30 |
| 胶囊表面圆角 | 999（底部导航、身份标签） |
| 圆形按钮 | 50%（按可视尺寸计算） |

状态反馈沿用所属控件/行的圆角，不另画不同形状的 hover 面。复合卡片行用 18，紧凑导航行用 12；聊天气泡的内侧下角使用控件圆角 12。圆角不写局部近似值，使用 `radii.control`、`radii.card`、`radii.panel` 或 `radii.pill`；圆形按钮按尺寸取半径。

图标统一使用 lucide，默认描边 1.8：

- 导航图标：22
- 动作图标：20–22
- 关闭等辅助图标：18

文字层级保持克制：页面/面板标题约 22px、弹窗标题约 18px；正文 14–16px（聊天正文 16px）；标签和辅助信息 12–13px，使用次要文字色。

## 5. 动效

| 场景 | 时长 | 曲线 |
| --- | --- | --- |
| 按下 | 90ms | cubic-out |
| 松开 | 160ms | cubic-out |
| 悬停 / 状态色 | 即时切换 | — |
| 主界面推开 / 归位（仅横向平移） | 260ms / 200ms | cubic-out |

- 按压缩放：图标按钮 0.94，Primary 0.95，底部导航图标 0.92，chip 0.98；整行不缩放。
- 系统启用“减少动效”时，所有位移与缩放时长为 0。抽屉仅平移主界面，不对大型聊天表面动画缩放、阴影或圆角裁切。
- 不使用循环呼吸、按压回弹或跨页面共享元素动画来表达普通按钮。

## 6. 状态矩阵

| 控件 | 默认 | 悬停（Web） | 按压 | 焦点（键盘） | 选中 | 禁用 |
| --- | --- | --- | --- | --- | --- | --- |
| 图标按钮 Secondary | 白底细边框 | `#F8F9FA` | 缩放 + `#ECEEEF` | 2px 焦点环 | — | 40% 透明度，无反馈 |
| 图标按钮 Primary | `#D6EEFF` | `#C8E7FF` | 缩放 + `#BCE0FC` | 2px 焦点环 | — | 退回浅灰底，40% 透明度 |
| 行 / 抽屉页签 | 透明 | `#F8F9FA` | `#ECEEEF` | 2px 焦点环 | `#F0F1F2` | 40% 透明度 |
| chip | `#F3F5F6` | `#EDF0F2` | 缩放 + `#E6EAEC` | 2px 焦点环 | — | 40% 透明度 |
| 文本按钮 | 浅灰或透明 | 背景加深 | 缩放 0.97 | 2px 焦点环 | — | 40% 透明度 |
| 文本输入 | 白/画布底、细分割线 | — | — | 使用主题焦点色；键盘另加 1px 环 | — | 不可编辑时无交互 |

上表矩阵使用浅色值；深色模式的背景、文本、边线与选中态取同名深色令牌。`TactilePressable` 的按钮焦点环为 2px；其他文本输入去掉浏览器默认黑色 outline，聚焦边框使用主题焦点色，键盘 `:focus-visible` 额外显示 1px 焦点环，鼠标聚焦不加环。聊天输入区在两种主题下聚焦时都不额外变色或显示外环，保留常规细边框与平台光标。选中复合行的 hover/按压使用对应的加深灰，且仍只由整行绘制一层状态背景。

| `TactileListRow` | `apps/mobile/src/components/TactileListRow.tsx` | 多个独立操作组成的一行共用卡片/紧凑表面、悬停、按压和选中状态 |
| `IconButton` | `apps/mobile/src/components/IconButton.tsx` | 图标按钮，支持 `card` / `soft` / `plain` / `primary` 和 `sm` / `md` |
| `TextButton` | `apps/mobile/src/components/TextButton.tsx` | 文本动作，统一内边距、按压和焦点 |
| `Screen` / `ScreenCard` | `apps/mobile/src/components/Screen.tsx` | 非聊天页统一滚动节奏、标题和卡片表面 |

| `ConfirmationDialogContent` | `apps/mobile/src/components/ConfirmationDialog.tsx` | 旁聊和产物删除共用二次确认内容；只能通过取消/确认按钮关闭 |
| `FloatingPanel` | `apps/mobile/src/components/FloatingPanel.tsx` | 设置、产物预览等盖在主界面上的上浮面板；统一遮罩、圆角、动效与滚动内容，可点关闭按钮或遮罩关闭；headerLeading 放内部返回，contentKey 只重置滚动内容 |

| `AppScrollView` | `apps/mobile/src/components/AppScrollView.tsx` | 需要显示滚动条的纵向滚动共用指示器配置；用于长内容和可滚动菜单 |
| `FeedbackToast` | `apps/mobile/src/components/FeedbackToast.tsx` | 应用级 5 秒短暂反馈，统一承载 info / warning / error |

| 令牌与主题 | `apps/mobile/src/theme.ts` | `ThemeProvider` 持久化设备外观偏好，`useTheme` / `useThemeStyles` 提供当前语义色板；并集中管理 `radii`、`controlSizes`、`motion` 与交互状态色 |

组件表现：

- 普通按钮由 `TactilePressable` 提供状态；图标按钮保持圆形，文字按钮和 chip 用控件圆角 12。
- 普通可展开项是 disclosure row：整行透明、hover/按压显示当前主题的中性灰，展开不是选中态，读屏暴露 `expanded`。
- 每个模型区块以左右并排的模型下拉框和思维强度下拉框呈现；两个控件保持相同高度，思维强度选项跟随当前模型，未选模型时禁用。菜单支持键盘和读屏单选操作。
- 文件预览和可滚动菜单共用 `AppScrollView`；滚动条采用平台默认样式，只有内容超出可视区域时才显示，并在平台支持时保持显示。共享 Markdown 表格至少铺满内容容器宽度，各列等宽且单列最小 160dp；列数过多时表格保留最小列宽并横向滚动。
- 操作后的短暂 info / warning / error 使用应用级 `FeedbackToast`；成功保存不提示。需要持续处理或重试的错误留在所属上下文，复用 `ErrorNotice` 或确认框/表单错误。同一失败只设一个主要反馈位置；列表失败不同时显示空态，恢复按钮写明具体动作，不用通用“重试”替代重新执行确认。规则与限制见[错误反馈与恢复](features/error-feedback.md)。
- 旁聊、任务和产物等含多个操作的列表行用 `TactileListRow`；`surfaceVariant="compact"` 用于紧凑导航行，`surfaceVariant="card"` 用于带边框卡片行。行面独占 hover/按压/选中背景，行内按钮保留自己的命中区但不重复铺背景。
- 内容卡片和复合卡片行用当前主题的卡片表面、细分割线和 18px 圆角；模型下拉触发框用 12px 控件圆角，选项菜单用 18px 卡片圆角，选中背景铺满整行并由外框裁切；浮层面板用 30px 顶角。
- 自己发送的聊天气泡使用当前主题的蓝色，助手气泡使用中性灰；聊天输入区用 30px 圆角。浅色与深色模式聚焦均不增加外框或焦点环，光标使用平台默认。
- 底部导航以单个当前主题的中性灰胶囊表达选中，不叠加第二层选中背景。

使用约定：

- 图标按钮优先用 `IconButton`，不要直接写 `Pressable` 圆角样式。
- 整行可点用 `TactilePressable` + `variant="plain"`，`scaleTo={1}`，不要在行上做缩放。
- 一行包含主操作和尾部菜单等多个独立控件时，用 `TactileListRow` 承载整行状态；子控件设置 `stateFill={false}`，悬停、按压和选中背景只由整行绘制，避免各自出现相互割裂的 hover 面。
- 列表行的状态背景覆盖完整行面；文字留白放在行内部，分隔线可单独缩进，不用列表容器的水平 padding 缩窄 hover / 选中区域。
- 有边框列表内的选项状态背景铺满整行，不在外层圆角容器里再叠一层圆角选中块；由列表容器裁切首尾边缘。
- 列表行、附件 chip 的交互背景由 `TactilePressable` 的 variant / state 控制；自定义 `faceStyle` 不要设置 `backgroundColor`，否则会覆盖悬停、按压和选中色。
- 底部导航与抽屉页签使用同一套当前主题的中性灰选中背景；悬停、按压和选中只保留一层状态背景。
- Web 文本输入移除浏览器默认黑色 outline；凭据输入与通用文本弹窗由外层输入表面显示主题焦点边框，键盘 `:focus-visible` 增加 1px 焦点环，鼠标聚焦不加环。聊天输入区在浅色与深色模式均不显示额外聚焦外框。
- 主操作只在真正可提交时使用 `primary`；不可用时退回 `soft` 并置灰。
- 重命名等单行文本输入复用 `TextInputDialog`，不在列表原地展开输入框。调用方预填当前值、提供保存回调；弹窗统一取消/确认、空白禁用、保存中锁定、错误提示、键盘避让和 Escape 取消。保存成功才关闭，失败保留输入；Enter 可确认。菜单切换输入时复用同一个 Modal 与 `TextInputDialogContent`，避免 iOS 连续呈现两个原生弹窗。
- 新增颜色、尺寸或动效前先检查 `theme.ts` 是否已有可用令牌。

## 8. Web 与原生

- 设置中的“外观”卡片提供“跟随设备 / 深色 / 浅色”下拉；偏好保存在当前设备，不写入模型或部署配置。Web 根据主题更新文档 `color-scheme`、浏览器主题色和滚动条色；原生界面与状态栏图标颜色随主题变化。
- Web：支持 hover、键盘 focus-visible、Escape 关闭浮层；点击按钮不显示焦点环。
- 原生：使用按下缩放和背景变化，不使用 Android 水波纹；系统返回键行为保持不变。
- 头像下方实时活动共用各端现有状态栏：整轮开始显示“工作中”，工具开始时在 3–5 字标签或“调用工具”前显示与 TG 一致的工具 emoji，正文输出显示“正在回复”。标签保留到下一活动覆盖，整轮结束后清空，不因工具/单条回复完成而回退。活动由服务端投影，加载、上传、停止和重连状态仍优先；聊天区不显示额外等待气泡，也不新增工具气泡。
- 所有平台共享同一套尺寸和状态，不为平台单独发明按钮样式。
- 设置、产物预览和执行结果等上浮覆盖面板共用 `FloatingPanel`，标题可选；无标题时不渲染空标题占位，关闭按钮仍右对齐保留。可点面板内关闭按钮或遮罩关闭；Escape 和系统返回不自动关闭。
- 旁聊和产物行菜单共用 `AnchoredMenuContent`，菜单可由外点、Escape 或系统返回关闭。单选菜单沿用当前主题的卡片底、细边框、轻阴影和 18px 圆角，各项至少 48px 高；当前项显示勾选与中性整行背景，由浮层外框裁切，不使用独立圆角选中块。单选菜单暴露 radiogroup/radio 与 checked 状态，选择立即应用并关闭；排序触发器使用圆形排序图标按钮，不在按钮上显示当前值，当前值只在菜单勾选中体现；按钮暴露 expanded 状态且有效命中区域至少 44×44。
- 产物排序在标题栏使用一个圆形排序图标按钮，与刷新并列；不展示当前排序值，也不另设升降序按钮。菜单列名称升序/降序、修改时间最新/最早在前，当前项勾选。子目录面包屑紧跟“产物”标题并占据可收缩空间，排序和刷新固定在右侧；路径过长时面包屑可横向滚动，不掉到标题下一行。破坏性操作共用 `ConfirmationDialogContent`，只由取消/确认按钮关闭，执行中禁用关闭和重复提交。
- 主聊和旁聊共用滚动规则：只挂载当前可见聊天的列表，切走卸载；刷新、首次进入和切回会话都从最新位置开始，不恢复旧阅读位置。初始跟随持续覆盖历史加载、顶栏状态和输入区尺寸就绪，会话数据、草稿、附件和请求身份仍按会话保留。
- “是否贴底”和“是否跟随”独立：离底超过 2 个布局单位才显示“最新消息”箭头；发送本地新消息或点击箭头恢复跟随，手动滚回底部同样恢复。用户拖动、上滚或键盘翻页解除跟随；历史快照、等待提示、正文增长与布局变化本身不能解除或重新抢回跟随。处于阅读位置时，恢复观察的 busy 快照不触发置底。
- Web 按真实滚动容器的尺寸同步置底，监听包含 padding 的完整内容与视口尺寸；自动跟随和点击箭头都直接定位，不启动会保留旧目标的浏览器平滑滚动。箭头依据实际位置隐藏，不用点击或发送状态假装已到达。加载更早历史保留可见消息的位置。原生使用列表尺寸/滚动事件，用户拖动时不自动校正。聊天输入区与底部导航仍共用一份实测高度，供列表留白、渐隐和按钮定位使用。
- App 助手消息使用 markdown-it-cjk-friendly 处理中日韩文字与标点相邻时的 Markdown 边界，使用 remend 补全流式显示；不改消息原文。流式更新保持同结构 Markdown 节点与气泡的展示身份，提交为正式条目不重挂载整条回复；语法补全引起的真实排版变化仍可能改变高度。Web 导出可用，原生设备上的实际显示仍需真机核验；Telegram 使用独立的富文本渲染链路。
- 旁聊删除必须先显示确认弹窗，说明不可恢复及不清理附件、工作区文件和历史备份。取消不发送 DELETE，提交期间禁用重复点击和关闭，失败保留确认框与重试；删除当前旁聊返回主会话。在线 deleted 通知或旧旁聊 404 会清空对应客户端状态并停止重连，不能把“断线重试”用于复活已删除会话。
- 聊天输入区与底部导航是共用容器，其实测高度只保存一份，供消息列表留白、底部渐隐和“最新消息”按钮共用，不按会话缓存；切换会话但容器尺寸不变时，不能依赖新的 onLayout 通知补高度。
- 触屏命中区域不足 44×44 时，用 `hitSlop` 扩大，不改变视觉尺寸。
- 模型设置立即反映选择，后台按修订号串行保存；保存期间仍可继续修改或关闭面板。失败先恢复上次确认的选择：面板仍开着时在内部说明并提供重新读取，已关闭时才显示全局 Toast。响应丢失不能据此宣称服务端未保存。

## 9. 可访问性

- 所有按钮必须有 `accessibilityLabel`；图标按钮不能只靠图形表意。
- 状态通过 `accessibilityState` 暴露：`disabled`、`selected`、`expanded`、`busy`。
- 键盘 Enter/Space 应能触发；焦点顺序与视觉顺序一致。
- 抽屉：底层全高铺到主界面左侧，以略深冷灰背景和 1px 细分界线表达层级，不做悬浮卡片边距、圆角或阴影；宽度为屏幕的 76%，最多 300。主界面只作为前景右移，不缩放、不重排内容；抽屉标题不放关闭叉号；可点击露出的前景表面、按 Escape 或 Android 返回关闭。菜单打开时主界面对读屏隐藏，焦点留在抽屉。旁聊三点菜单的图标与文字整体左对齐。
- 禁用控件仍保留在可访问性树中，并向读屏说明当前不可用。

## 10. 修改规则

1. 新按钮先选层级，再选组件，最后才写局部样式。
2. 同一页面出现第二个 Primary 时，先确认是否真的需要。
3. 新增状态（例如 loading、danger、toggle）时，先补充本文档和令牌，再落代码。
4. 交互改动需要在 Web 和至少一个原生目标上验证；未验证的范围在文档中注明。
5. 本文档与 `docs/PRODUCT.md` 冲突时，以产品行为为准，并同步修正本文档。
