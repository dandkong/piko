# 旁聊

旁聊是用户主动创建的独立聊天，不是主聊天分支或后台工作。每个旁聊有独立历史、上下文、停止和压缩状态；应用重开和 Chat 导航默认回到主会话。

## 产品范围

从抽屉新建旁聊并直接进入；标题在成功回答后仅对空标题异步生成，也可手动重新生成。删除需要确认且不可恢复，删除当前旁聊后回到主会话；不提供归档或恢复。

旁聊共享工作区、技能、通用工具及全局主模型，但不继承主会话历史、不自动回传主会话，也不参与主会话的记忆整理。可委派后台工作，结果和状态只属于发起旁聊；不提供保存任务管理工具。Telegram 只接主会话。

导航抽屉铺在全高底层，宽度为屏幕 76%、最多 300；主界面只横向平移，不缩放或重排。点击露出的主界面、Escape 或 Android 返回可关闭；打开时对读屏隐藏主界面。选择页签或旁聊后抽屉归位。主聊和旁聊聊天交互见[主会话](main-chat.md#聊天界面交互)。

## 运行时

旁聊使用 Durable ownerless conversation；创建元数据和请求回执使用原生文档，不另建消息或运行状态存储。输入、停止、维护和内部报告经各自会话控制器；查询和后台委派按会话所有权隔离。启动刷新旁聊的前台模型和工具选择，不改写历史。

## HTTP

`/api/side-chats` 提供列表和创建；`/api/side-chats/:id` 提供标题生成与确认后的删除。对应 `/chat`、`/chat/history`、`/chat/events`、`/chat/stop` 复用主聊天的提交、历史和 SSE 语义。实体 ID 对外视为不透明字符串。

## 永久删除边界

删除先停止并清理旁聊及其后台工作，再移除所属会话、执行记录和客户端状态；失败可重试，重启时恢复未完成清理。不删除主会话、其他旁聊、附件、工作区文件、产物、备份或供应商记录，不回滚外部副作用，也不保证全介质擦除。详见[存储维护](../operations/storage.md#共用删除协议)。

## 前端状态与恢复

各聊天保留独立草稿、附件、历史和请求身份；切换或断线只停止观察，不停止执行。重新进入从最新快照恢复；已删除会话不重连。应用重开不恢复旁聊选中状态。请求和错误恢复见[错误反馈](error-feedback.md)。

## 验证状态

主要服务端行为和 Web 交互已在隔离环境检查；原生设备、真实模型和 Telegram 网络行为仍需验证。
