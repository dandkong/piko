# 设置与模型配置

状态：设置页直接提供全局主模型与后台模型选择、供应商凭据管理和模型目录编辑。配置管理目前是**未鉴权的功能验证版**，不应向不可信网络开放；鉴权将后续单独接入。

## 入口与导航

- 抽屉左下角“设置”直接打开共用 `FloatingPanel` 中的模型配置；不展示工具、通道、工作区、版本等只读分类。
- 页面只保留实际可配置项：主/后台模型使用锚定浮层下拉选择、供应商 API Key 和高级模型目录；不提供“跟随主模型”选项。模型选项浮在页面上方，不撑开设置内容；空间不足时向上展开。设置只通过明确关闭按钮关闭；存在未保存草稿时会先询问是否放弃。
- 打开时读取模型列表与配置快照；读取失败时可重试。修改使用基于配置修订的乐观并发校验，冲突时保留草稿。

## 用户模型语义

- 用户只配置一个全局**主模型**与思考强度，用于主聊天和所有旁聊。App 与 Telegram `/models`、`/thinking` 写入同一配置，不提供每个前台会话单独的模型选择。
- JSON `agent.profiles.main` 是主模型事实源；Durable AgentDoc 保存 SDK 当前执行所需的模型投影。启动时主聊与旁聊都对齐 JSON；运行期间主模型变更不会改写忙碌会话，当前轮完成后、下一轮开始前对齐。配置一致时不重复写 AgentDoc。
- 首次没有主模型时不会自动选可用目录中的第一个；设置仍可用，主模型执行会提示先选择。
- 后台模型单独选择并保存到 `agent.profiles.background`；未单独配置时以当时的主模型作为初始值，之后主模型变化不会带动后台模型。已启动的后台工作不因配置变更中途切换。

## 模型管理能力

- 主模型和后台模型从当前已加载且有可用凭据的模型中选择；每个模型只显示支持的思考强度，App 用中文等级单选列表呈现。
- API Key 状态只显示是否配置和来源，不回传密钥。空输入表示保留；输入新 Key 会写入 `auth.json` 并清理同供应商旧的 `models.json` 内联 Key。明确删除会移除两处的 API Key。OAuth 条目不能通过普通 Key 表单覆盖或删除。
- `models.json` 目录通过经 schema 校验的非敏感 JSON 编辑；其中的 `apiKey` 不返回，也不能从 JSON 编辑器写入。修改模型目录或凭据需要重启；保存前明确确认，服务保存后按 systemd 运行策略重启。Durable 不会自动重放不确定执行。
- 只修改主／后台模型时不重启服务；服务发布新主模型策略后，空闲会话立即对齐，忙碌会话在下一轮前对齐。
- 编辑模型目录及凭据当前采用 JSON 目录编辑器作为功能验证入口；后续可用结构化供应商／模型表单替换常见操作。工具、技能、Telegram、部署值及 OAuth 授权仍只读/未接入。

## API 与保存

- `GET /api/settings` 只返回模型选择器需要的可用模型列表与当前主会话模型；`GET /api/settings/config` 返回修订号、模型选择、脱敏模型目录与凭据状态。
- `PUT /api/settings/config` 接受主／后台模型、非敏感目录及显式 Key 操作。拒绝未知字段、内联 `apiKey`、非法模型目录、无效引用和陈旧修订；正文限制 1.1 MB。
- `piko.json`、`models.json`、`auth.json` 使用同一私有事务日志、同目录临时文件与原子 rename 写入；异常或启动恢复时回滚未完成事务。事务备份权限限定在 PIKO_HOME 的私有状态目录。
- 设置 API 及配置写入目前**没有内置鉴权**。这是用户明确要求先进行功能验证的临时状态；监听地址当前可能允许网络直连。实施鉴权前不得视为可公开的管理能力。

## 代码位置

- `server/settings/configuration.ts`：修订校验、模型／凭据脱敏、schema 校验、原子事务与启动恢复。
- `server/settings/http.ts`：只读概览、配置读取／写入和受控重启调度。
- `server/runtime/pi.ts`、`conversation-session.ts`、`bootstrap.ts`：统一主模型、前台 AgentDoc 安全边界和 Telegram/App 共用配置路径。
- `apps/mobile/src/features/settings/`：模型编辑、凭据输入、草稿确认与保存状态。

## 验证

隔离配置文件测试覆盖密钥不回显、内联 Key 迁移、JSON schema 拒绝、revision 冲突及事务中断回滚。faux Durable runtime 测试覆盖 App/Telegram 共用全局主模型、主聊和旁聊的 AgentDoc 对齐、重启重新对齐、忙碌会话当前轮保持旧模型而下一轮应用新模型。HTTP 测试覆盖保存、并发冲突、正文上限、敏感字段不返回和重启调度。Chromium mock 页面验证了主／后台模型编辑、Key 替换不回显、模型目录变更确认、无效 JSON 禁止保存、取消重启、草稿关闭确认及窄屏布局。类型检查与 Web/iOS/Android Expo 导出通过；没有用真实凭据调用供应商，尚未做原生真机操作验收。
