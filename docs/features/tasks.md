# 任务与执行记录

任务是保存的工作指令，可手动、一次性或按 Cron 运行。用户在 Chat 交办，在 Tasks 查看和管理；业务类型 `AssistantTask` 与 Durable 原生任务不同。一次运行是一次执行，归档停止未来调度并保留历史，不等于执行完成。

## 产品交互

列表按进行中/已归档分组，活动任务可手动运行、归档或删除，归档任务可恢复或删除。任务详情显示指令、时间和已结束执行的结果；运行中的执行不进入时间线。创建、编辑和停止通过聊天完成。删除需确认，仍在运行或回传的任务不能删除。

任务文件夹是助手工作区而不是正式产物；用户需要交付文件时可让助手保存到 Artifacts。详情不提供任务文件浏览。

## 持久化与目录

定义、调度游标和执行关系保存在 Durable 原生文档；执行状态及回答从原生任务和 entries 投影，不复制 Run 或消息正文。每次执行创建独立子会话，使用共享工作区和该任务的 `tasks/<id>/MEMORY.md`；多次执行共用任务目录，不继承主聊天历史。文件和 cwd 不是沙箱。参见[Agent 构建](agent-composition.md)。

删除任务清理其定义、历次执行和专属任务目录；不删除主会话已有报告、附件、其他工作区产物或备份，不回滚外部副作用。删除与中断恢复见[存储维护](../operations/storage.md#共用删除协议)。

## 时间、并发与幂等

调度支持手动、带偏移量的单次时间和带 IANA 时区的五字段 Cron。每个任务最多一次执行，全局最多两个任务执行。手动运行不改变调度；恢复归档重新启用未来调度，不立即运行。命令使用 requestId 去重；同一身份不能提交不同内容。调度及错误恢复细节以服务实现为准。

## 回传与恢复

执行结果以内部报告交回主会话，由主助手整理；子会话原文不直接投递。主聊天普通停止不取消独立任务；显式停止任务不改变未来调度。重启取消不确定执行，只恢复已完成结果的回传，不重放模型或外部操作。Telegram 无可靠补发保证。

## HTTP 与工具

任务接口位于 `/api/tasks`，提供列表、定义、执行记录和任务操作。主 Agent 使用 `task_list`、`task_get`、`task_create`、`task_update`、`task_run`、`task_stop`、`task_archive`、`task_restore`；永久删除仅由用户在页面确认。工具与 API 复用业务服务；参数以 `shared/tasks.ts` 和工具 schema 为准。

## 验证状态

生命周期、调度、权限、回传、删除及恢复已在隔离环境检查；真实模型、Telegram 和原生设备的端到端表现仍需验证。
