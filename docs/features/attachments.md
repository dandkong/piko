# 附件与图片读取

Web、iOS 和 Android 聊天支持选择文件并上传；Web 还支持粘贴浏览器提供的文件或截图。原生选择与上传已完成类型检查和 bundle 导出，尚未真机验证；原生图片粘贴和聊天图片缩略图尚未接入。

## 统一附件存储

用户上传、Telegram 下载及助手发送的快照保存在 `PIKO_HOME/state/attachments/`，不在工作区内；上传保留安全化原文件名，各次使用独立身份。Piko 接收和发送的单文件上限为 100 MiB，Telegram 另有平台限制。附件不自动过期，备份 PIKO_HOME 时应一并保护；手动删除文件会使历史链接失效。

## 助手发送文件

主会话和未归档旁聊可调用 `send_attachment(path)` 发布非空普通文件的独立快照；不跟随最终路径符号链接。后台工作和任务不能直接发送，可将文件路径交给发起会话的助手。主会话附件尽力同步 Telegram；失败不会回滚会话，也不自动补发。

## 展示与音频预览

附件显示文件名，支持预览和单独下载；Markdown/文本预览与 Artifacts 共用类型和 1 MiB 限制。支持的 MP3、M4A、OGG、WAV 可在客户端播放，实际格式取决于浏览器或设备；不自动转写或转码。原生播放及下载仍需真机验证。

## 入口

| 来源 | 行为 |
| --- | --- |
| Web | 选择文件或粘贴浏览器提供的文件/截图，上传后由用户发送 |
| iOS / Android | 系统文档选择器多选，复制到应用缓存后上传；失败可重试，超出已知上限提示重新选择 |
| Telegram | 接收图片、文件和音视频，相册按消息分别处理 |

App 上传通过 `POST /api/attachments` 发送原始字节，聊天请求使用 `attachmentIds`，单条最多四个。上传中的待发送文件排队；系统缓存可能被清理。大文件会占用客户端和服务端内存。

## 模型看到什么

服务端将附件本机路径与用户输入交给模型。图片可用 `read` 处理，其他文件由模型选择文件或命令工具检查；PDF/Office 不自动提取正文。模型缺少图片能力时不能声称已看过图片。工具和文件访问使用后端实际权限，不是沙箱。

## 验证边界

Web 上传与文件流程已在隔离环境检查；原生文件选择、上传、播放与保存以及真实 Telegram 文件投递仍需设备和网络验证。
