# 工作区与主会话模型

状态：会话和执行状态使用 Durable 原生 SQLite，不维护 Piko 自建消息/Run 表。存储维护见[SQLite 说明](../operations/storage.md)；架构见[架构说明](../ARCHITECTURE.md)，模型与运行时见[Agent 运行时说明](../operations/agent-runtime.md)。

## 范围与初始化

一个 PIKO_HOME、一个长期工作区、一个 Harness/root 主会话；后台委派使用同一 Harness 的持久化子会话，不增加展示，见 [后台子 Agent](background-subagents.md)。[任务与执行记录](tasks.md) 已在同一 Harness 接入，Tasks 按进行中/已归档展示任务与执行记录，并支持归档/恢复；归档不等于单次执行完成。每日/长期记忆整理已接入；[旁聊](side-chats.md) 已复用同一 Harness 接入独立用户聊天，不参与主会话的记忆提取。Artifacts 浏览、下载和确认删除工作区 `artifacts/` 中的文件；任务目录中的执行产物暂不聚合，见[产物浏览](artifacts.md)。

默认 PIKO_HOME 为 ~/.piko，仅部署环境 PIKO_WORKSPACE 可指定绝对工作区；配置见[应用配置](../operations/configuration.md)。初始化只补缺失配置和模板，保留用户内容。state 在工作区外，通过后端锁限制单写进程。已有主会话 cwd 与配置不同则拒绝启动，恢复原路径或使用新 PIKO_HOME。

| 存储 | 内容 |
| --- | --- |
| config/piko.json、.env | 应用配置与可选覆盖 |
| config/piko.json、models.json | 统一的非敏感 Agent/通道/工具行为，以及独立模型目录；不再生成 settings.json |
| config/.env 与进程环境 | 部署参数与敏感凭据，不覆盖 JSON 行为 |
| state/durable/ | session.sqlite（及运行期 WAL/SHM），唯一持久会话与执行状态来源 |
| state/tmp/ | 工具溢出与可清理临时文件 |
| 当前进程内存 | 流式消息、输出合并、Session 中待挂接的后台回传、TG 投递身份 |
| workspace/ | AGENTS.md、MEMORY.md、memory/ 每日记忆、技能与工作成果 |

没有 Piko 身份表、执行表、输入哈希、正文副本或永久 SSE 日志。停止去重和中断提示使用原生文档，不重复保存任务状态。当前持久化只支持 Durable 原生 SQLite，不提供旧格式导入。

## 展示与上下文

展示从原生原始 entries 正序投影用户/助手文字，保留 reset、上下文编辑和压缩前历史。气泡 ID 直接使用 Durable 原生 entry ID，时间来自原生消息。工具调用、思考、隐藏 entry 和压缩摘要不作为聊天消息显示；头像状态栏可短暂显示已知工具活动或回复状态，这些实时状态不进入历史。

Web/RN 的首次快照与后续 SSE 快照只传最近 50 条可见已保存消息，另附当前流式消息与未应用输入。`GET /api/chat/history?before=<entry ID>` 向前读取至多 50 条，`nextBefore` 表示还可向前翻页；游标基于不可变 entry ID，新增消息不会移动旧页边界。每页与状态在原生 commit 线上读取；提交绑定从原生 submission 初始化并随 commit 更新，不新建正文或永久索引。

客户端向上滚到顶部附近自动加载更早消息，可手动点击加载或失败重试；加载时保留阅读位置。最近快照覆盖所含范围及临时输入，不清掉已经翻出的更早记录。失联期间若增长超过最近窗口、与客户端记录无交集，则重置到最新页，避免掩盖中间缺口；旧请求的分页响应不混入新窗口。客户端仅加载访问过的页，但目前不会自动淘汰已加载页；服务端运行时仍保留完整原生历史用于事件恢复，启动与运行时内存不因此变为常量。

每条用户消息从原生 submission.entry 获取 requestId，不额外写输入记录。助手消息独立展示，不累计整轮回答、不强行配对。当前流式消息采用临时 ID，保存后原位替换；原生 inbox 里的未应用输入临时显示，撤回后消失。模型上下文和压缩由 Durable 处理，UI 不读取压缩后的 context 代替历史。

## 执行、停止与传输

POST /api/chat 接收 {requestId,message}，返回原生提交回执。RN 新请求生成 UUID，网络重试保持该 ID；TG 使用 telegram:<botId>:<chatId>:<messageId>。同 ID 返回原提交；用户主动重试使用新 ID，连接恢复只观察、不自动重发。去重依据 requestId，不使用内容哈希或前次执行关联。

输入、停止与维护预留由 DurableChatSession 的单一接纳线协调；ConversationStore 只负责文本校验、输出合并与观察，不重复维护锁或后台回传缓存。普通输入使用 whenBusy=steer 与 steeringMode=all，运行期间仍可接纳，在原生边界全部应用；不强行打断模型或工具。模型/思考选择及手动压缩占用空闲边界，期间普通输入立即拒绝；停止可取消压缩。

GET /api/chat/events 是持续会话 SSE，与每条输入提交分开。公开事件仅有 snapshot/message/activity/error/deleted，内部状态失效、工具开始/结束和压缩生命周期不直接透传；完整契约见[会话事件与实时活动](conversation-events.md)。每次连接先发送最近一页的 authoritative snapshot（含从原生 LiveDoc 恢复的当前活动），再继续实时更新；不使用事件游标和重放缓存，不补齐断线期间的中间流式事件。首次快照与实时订阅仍衔接在同一发布线上，防止漏掉期间的变化。消息更新最多 50ms 合并，15 秒心跳，客户端 30 秒无数据重连并有限退避。断线、页面卸载和退后台均只退订，服务端继续工作。

POST /api/chat/stop 以独立 requestId 停止 conversation 和待应用输入。原生 piko.stop 文档记录当时的 task ID，重复请求只取消原目标，不影响之后的新工作。执行失败也结算和撤回剩余输入；未落入原生用户 entries 的输入不进入最终历史。提交状态使用原生 queued/placed/done/unanswered，不另存 Piko 终态。

RN 在前台持续观察两通道变化，原生快照加未确认的本地输入构成列表；过期 HTTP 刷新不会覆盖较新的观察结果。TG 按助手消息维护投递，网络发送不阻塞接纳或执行。接口见 [架构说明](../ARCHITECTURE.md)，通道边界见 [Telegram 通道](telegram-channel.md)。

## 资源与工具

核心指导随应用发布，工作区保存由用户定制的指导与记忆文件。注入时标注来源路径和 `role`，职责如下：

| 文件 | role | 职责 |
| --- | --- | --- |
| 应用 `core.md` | core | 应用运行规则、工具使用与结果真实性，不固定助手名字或语气 |
| 工作区 `AGENTS.md` | work_guidance | 助手身份、默认表达方式及通用工作/流程规则；默认名字 Piko 在此定义。用户特有的沟通、工作、决策偏好和协作边界归 MEMORY.md |
| 工作区 `MEMORY.md` | memory | 稳定且跨会话有用的信息：用户背景与长期目标、明确偏好、长期边界/确认要求、长期项目目的/约束/资料位置、已验证的可复用经验；不是聊天记录，也不授予一次性操作权限 |
| 工作区 `memory/YYYY-MM-DD.md` | memory（按需读取） | 精简的每日事件层：目标与进展、事实/状态变化、决策及理由、待办/阻碍、明确偏好/边界、未解决问题与有价值的建议/跟进条件；区分确认、建议和待验证信息，不作每日对话摘要，也不自动注入 |

助手身份、默认表达方式和通用操作流程放在 AGENTS.md；用户背景、长期目标、明确的沟通/工作/决策偏好、协作边界、长期项目约束及已验证经验放在 MEMORY.md；会变化的目标进展、决定、待办和跟进线索放在按日期组织的 `memory/YYYY-MM-DD.md`。用户特有偏好与助手通用规则分开保存，避免重复；记忆可保存持续的限制或确认要求，但不替代当下授权。

`role` 是资源用途标注，不是独立的模型消息权限层级，也不构成安全隔离。实际能力与文件访问边界必须由运行时实现。

### 会话历史检索

Agent 可调用 `sessions_search` 搜索当前会话，再把返回的 `sessionId` 与 `messageId` 交给 `sessions_history` 读取锚点附近的有限上下文。主会话只搜索主会话；旁聊只搜索自身。普通后台子 Agent 不提供这两个工具；[Posts 专用研究角色](posts.md)通过宿主绑定复用它们，只能查询 root 主聊天且受本轮历史截止 entry ID 限制，不能自行指定其他会话。

搜索范围与聊天历史的可见投影一致：只检索用户/助手文本，不检索隐藏的内部输入、工具调用/结果、推理内容或附件正文；内部回报之后正常显示的助手答复仍可检索。查询按 Unicode 兼容形式与大小写规范化；空格分隔的词必须同时出现在同一条消息中。结果按时间从新到旧排列，附短摘录和 Durable 原生数字 entry ID；调用 `sessions_history` 时直接传 ID 字符串。历史读取最多返回 20 条消息，每条正文最多 500 字符；返回窗口中的消息 `id` 也可作为下一次锚点。锚点无效或不属于当前会话时返回未找到，不回退到最新历史。

V1 直接分页扫描 Durable 原生 entries，不使用 FTS5，也不持久化正文副本或搜索索引。搜索完成整段历史扫描后最多返回 25 条结果，并标明是否还有未返回的命中；它不承诺大历史下的索引级搜索速度。

core.md、工作区 AGENTS.md 和 MEMORY.md 均完整读取，不设应用层字符/字节上限，也不静默截断；后台任务自己的 tasks/<id>/MEMORY.md 同样完整读取。实际可用上下文仍受所选模型窗口约束；静态文件内容过大时，底层可能压缩聊天历史，但如果总请求仍超过模型窗口，也可能由模型服务拒绝。应用不会为规避窗口错误而静默丢弃文件尾部。每次模型请求重新加载指导和技能索引，技能正文通过 read 按需读取；每日记忆不自动注入，相关时由助手通过工作区 read/search 查阅。初始化只补缺失的 AGENTS.md、MEMORY.md，模板升级不覆盖已有用户文件。系统只加载这两份工作区指导文件；其他 Markdown 文件不会自动加载、删除或搬移。

### 每日与长期记忆整理

主会话结束并闲置 30 分钟后，只有上次整理游标之后累计至少 3 条有可读文本的外部用户消息，才运行独立 Durable 后台整理 task；门槛只计主会话用户提交，不计助手回复或工具结果。少于 3 条时不调用模型、不推进游标，后续主会话消息继续累计；达到门槛后仍需再次满足 30 分钟空闲。整理输入包含游标后的主会话用户/助手文本，不含内部子 Agent 回报和工具日志，也不回填功能启用前的历史；批次不按凭据格式扫描或替换正文，整理提示会要求不将凭据写入记忆，但这不是程序级检测保证。没有可读文本时只推进游标，不调用模型。整理只由后台调度触发，不提供主 Agent 手动触发工具，也不向主聊天回报。

一个 整理 task 启动专用子会话，只配置 `read`、`write`、`edit` 三个工具，由 整理者 读取当前文件并直接编辑；不提供 bash。一次整理同时维护两类记忆；为了使用文件工具，模型可能经历多个工具调用轮次。

记忆整理不只是添加信息，也要维护已有内容。根据明确的新信息更新或合并旧条目，删除被取代、重复或已失去未来用途的内容。保留有意义的历史结果与必要的不确定性，不因时间过去或没有后续消息就判定事项结束、偏好改变。该原则适用于本轮读取的记忆，不扩大历史文件扫描范围。

- `memory/YYYY-MM-DD.md` 是精简的 episodic 事件层，不是每日摘要或原始 transcript。按日期记录会影响未来判断、协作、行动或跟进的信息：目标/进展/约束，事实和状态变化，决定/理由/未选方案，下一步/阻碍/依赖，以及用户明确表达的偏好和行动边界；也可记有价值的未解决问题或建议。记录时区分用户确认、Agent 建议和待验证推测；不得把建议写成承诺，也不得臆造负责人、期限或触发条件。必要时保留来源、报告路径或验证限制；不复制完整报告，不写闲聊、常规工具日志、重复内容或凭据。允许就地更新、合并和精简已有条目；状态变化应收敛到同一事项，保留必要的日期与结果，避免过时状态与最新状态并存。
- `MEMORY.md` 只保留稳定、跨会话有用并会影响未来协作的信息：用户背景与长期目标；明确的沟通/工作/决策偏好；持续的行为边界和确认要求；长期项目目的、关键约束与资料位置；已验证、可复用的经验。读取现有文件后合并去重，按明确纠正更新过时条目；不提升临时状态、单次任务、Agent 建议或未验证推测。助手身份和通用操作流程仍归 AGENTS.md；MEMORY.md 可以记录持续限制，但不能授予一次性权限或替代明确确认。

游标、活动 task 和重试状态存于 Durable 文档，不写进记忆正文。整理者读取 AGENTS.md 作为只读去重参考，并被提示只改 `MEMORY.md` 和本批对应的日期文件；但这只是行为约定，不是权限沙箱：三个工具使用后端本机权限，`write`/`edit` 仍可指向任意路径。文件写入与 Durable 游标不在同一事务；task 中断时不自动续跑，游标不推进，下一次整理会先读取当前文件再处理原范围。程序不做文件哈希冲突检测、回滚或写入结果独立校验；发生并发改写或模型未正确落盘时，保护能力有限。

技能来源为工作区 `.agents/skills` 与应用内建技能；同名时工作区版本优先，同名覆盖有诊断。`PIKO_HOME/skills` 不创建也不读取。不继承个人 Pi CLI、祖先指导或全局扩展。模型配置独立于 Pi CLI；Durable Extension 只由 Piko 内建代码注册，用户 skill 不增加运行时工具。

read/write/edit/bash 保持启用，相对路径默认工作区，本机 Shell 执行命令。`WorkspaceExecutionEnv` 除进程环境外，只将显式白名单的用户技能变量从 `PIKO_HOME/config/.env` 传给 Shell，不整体导出应用凭据。cwd 不是沙箱；目前没有操作审批 UI。durable 的 read 已能读取图片，附件存储与上传接口见 [附件与图片读取](attachments.md)，RN 选图仍是占位。记忆整理已实现；专门的记忆浏览、检索和版本管理 UI 尚未实现。

## 中断与损坏恢复

1. 启动取得锁、打开固定 state/durable/session.sqlite，校验原生存储、root 与工作区关联。
2. 损坏数据库、目录含不受支持的旧格式，或非空目录缺少 session.sqlite 时拒绝继续，不初始化空会话或静默回退。SQLite 处理 WAL 事务恢复。
3. 启用调度前撤回遗留输入并取消不确定执行；仅保留已完成子任务的 Reporter report 阶段，随后 resume 回传结果，不自动重跑模型和工具。
4. 有遗留生成或输入时写原生 piko.recovery 中断提示和隐藏上下文说明，不复制输入、不调用模型；下一次接纳清除提示。
5. 已保存历史继续展示；尚未保存的文字不保证恢复。恢复不回滚工具的外部副作用。

## 备份与恢复

停止 API 后备份整个 PIKO_HOME 和单独指定的工作区；SQLite 目录成套保存，恢复时使用原工作区绝对路径。需要清空数据时，应先确认并备份，再停止后端；不要只删除数据库主文件而保留 WAL。当前没有从旧格式导入会话数据的工具。

## 后续与验证

原生文档、任务、conversation 与 write submission 可承接未来产品状态和被动结果；任务调度、后台委派及已完成结果的回传恢复已接入；[旁聊交互](side-chats.md) 已接入；可靠投递 outbox 和权限尚未实现。

真实设备网络、前后台、键盘和长对话仍需使用验证。
