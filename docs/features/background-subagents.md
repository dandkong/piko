# 后台工作与子 Agent

后台工作是助手直接委派的独立工作；用户不需要理解子 Agent，代码和工具保留 `subagent` 名称。它不同于可反复运行的[保存任务](tasks.md)。子会话不作为聊天页面展示，结果只回到发起它的会话，由该会话助手决定如何处理。

## 共享资源与会话

后台工作使用同一 Harness、工作区、基本工具和技能索引；新建子会话不继承父聊天历史，也不自动加载全局指导和记忆。后续补充可继续已有子会话。后台模型未单独配置时跟随主模型；已启动工作保留自身模型选择。共享文件和 cwd 不是沙箱。

主会话和旁聊可委派；旁聊的工作、状态和报告限定在该旁聊。后台子 Agent 不能继续委派或管理任务。保存任务复用后台执行机制，但具有自己的任务目录和记忆。资源策略见[Agent 构建](agent-composition.md)。

## 委派与回传

主助手可使用 `subagent_spawn` 创建工作、`subagent_send` 补充输入、`subagent_list` / `subagent_status` 查看，以及 `subagent_stop` 停止；结果自动以内部报告回传，不需要循环轮询。主会话普通停止不停止独立后台工作；结果被父助手处理后无法撤回。子会话的原文和工具过程不直接投递到用户通道。

## 原生实现与持久化

每次委派创建受所有权约束的 Durable 子会话，Anchor/Reporter 负责持久执行和报告，状态和正文来自原生任务与 entries。内部报告必须经过发起会话的接纳线，不能绕过所有权和取消检查；不另建 Run 或正文副本。

## 停止、失败与重启

显式停止撤回尚未处理的相关报告并取消子会话当前执行；已经应用的报告和外部副作用不会回滚。失败由父助手处理。重启取消不确定执行，只恢复已完成结果的报告，不自动重放模型或工具；请求去重不保证外部操作恰好一次。

## 保留与清理

旁聊和保存任务的后台执行随所属对象删除；主会话下无长期业务归属的临时工作按 7 天保留期回收。运行中、等待报告或仍有依赖的工作不回收；父会话历史、工作区文件和产物不随临时执行删除。详见[存储维护](../operations/storage.md#临时执行的保留期)。

## 验证状态与限制

委派、停止、范围和恢复已在隔离环境检查；真实模型及 Telegram 网络行为仍需验证。没有独立后台工作管理页面或可靠通知补发。
