# App 与 Telegram 双通道

Telegram 是可选的单用户私聊入口，与 App 共用工作区、主会话、模型和执行状态；不要求两端界面功能完全一致。Telegram 不接入旁聊或直接展示后台子会话原文。

## 命令与菜单

| 命令 | 用途 |
| --- | --- |
| `/status`、`/recent` | 查看状态与最近已保存的聊天摘要 |
| `/models`、`/thinking`、`/compact` | 选择主模型、思考强度和手动压缩 |
| `/subagent`、`/task` | 只读查看主会话后台工作、任务及结果 |
| `/posts`、`/skills` | 只读浏览已发布帖子与技能 |
| `/stop`、`/exit` | 停止当前会话工作、关闭后端 |
| `/start`、`/help` | 欢迎和命令说明 |

按钮与命令只作用于已授权的私聊，命令反馈不进入模型历史。图片、文件和音视频通过[附件流程](attachments.md)接收；相册按消息分别处理，不自动转写语音。编辑旧 Telegram 消息不修改聊天历史。

## 会话、并发与输入去重

两端普通输入进入同一主会话；执行中可补充，不强行中断已开始的模型或工具。Telegram 输入使用稳定消息身份去重。App 的断线或后台切换只停止观察，不停止服务端执行；回前台重新连接并读取快照。

后台结果先交给发起它的助手；主会话产生的助手回复会投递 Telegram，无论最初输入来自 App 还是 Telegram。App 用户输入、旁聊及后台子会话原文不直接投递 Telegram。

## 回复呈现与投递

每条助手消息独立流式呈现；工具活动使用临时消息，执行结束后清理。文本和附件的发送失败不回滚会话，也不重新执行模型。投递状态仅在内存，没有可靠 outbox：重启或网络异常可能漏发，超时重试也可能重复。事件投影见[会话事件](conversation-events.md)。

## 配置与生命周期

在 `piko.json` 启用 Telegram 并指定数字用户 ID；Bot Token 放在私有 `.env` 或进程环境的 `PIKO_TELEGRAM_BOT_TOKEN`。配置与示例见[应用配置](../operations/configuration.md)。仅接受该用户的普通私聊；long polling 需要后端出站网络，同一 Bot 只运行一个 poller。配置变更后重启。

## 验证状态与限制

命令、鉴权范围和呈现在隔离环境检查；真实 Telegram 网络、长对话和原生设备后台行为仍需验证。群聊、主动推送和可靠补发尚不支持。
