# 会话事件与实时活动

Durable 原生状态是事实来源。`ConversationView` 将原始 entries 和实时状态投影为 Piko 运行时事件；App 通过 `ConversationStore` / HTTP / SSE 观察，Telegram 使用同一运行时事实进行通道呈现。观察者不拥有执行生命周期。

## 客户端协议

SSE 只提供 `snapshot`、`message`、`activity`、`error`、`deleted`；契约定义在 `shared/chat.ts`。每次连接先读取最近快照再观察实时变化，不保存永久事件日志或补放游标。重连不重新提交输入；聊天历史从原始 entries 分页读取，不能用压缩后的模型上下文代替。

## 实时活动

活动是临时投影：空闲、思考、回复或工具调用。最近一次工具开始或正文输出覆盖状态，执行结束时清空；工具结束本身不回退状态。头像状态栏按工具类型展示，`tool_search` 显示“搜索工具”，未知工具显示“调用工具”；不展示普通工具参数或新增聊天气泡。加载、上传、停止和重连状态优先。

## Telegram 有序呈现

Telegram 用同一串行队列呈现正文、临时工具活动和执行边界；结束时清理临时工具消息。主会话助手输出不按输入来源筛选，App 输入及旁聊/子会话原文不直接投递。网络发送失败不回滚执行或重跑模型；重启可能漏发，不承诺可靠补发或恰好一次。详见[Telegram 通道](telegram-channel.md)。

## 验证边界

事件投影、快照、活动及通道顺序已在隔离环境检查；真实网络和原生设备后台行为仍需验证。
