# 主会话

主会话是 Piko 的默认对话入口。App 与可选 Telegram 共用主会话；旁聊和后台工作是同一 Harness 下的独立会话。相关边界见[旁聊](side-chats.md)、[后台工作](background-subagents.md)和[双通道](telegram-channel.md)。

## 展示与上下文

UI 从 Durable 原始 entries 投影用户和助手消息；模型上下文压缩不删除用户可见历史。初次加载最近 20 条，向上分页并保持阅读位置；断线重连读取最新快照，不重投输入。没有第二套消息正文或永久 SSE 日志。尚未保存的流式文字在后端重启时可能丢失。

## 聊天界面交互

主聊与旁聊共用聊天布局和交互。空会话保持空白；助手消息显示 Markdown，用户消息保留原文。Web 使用 Enter 发送、Shift+Enter 换行，中文选词确认不发送；原生回车提交并保持焦点。回复期间仍可补充输入；有草稿时显示发送，回复中且草稿为空时显示停止。加载、发送接纳和停止期间不可重复提交。

聊天列表铺满可用空间，头部、输入框和底部导航悬浮其上；头部渐隐覆盖实测头部并向下延伸 12px，底部渐隐覆盖输入框至屏幕底部并向上延伸 32px；列表留白分别按头部底边与输入框顶边加 13px。头像留在身份胶囊外，空闲不保留状态行空位。

首次进入、刷新或切回会话时从最新消息开始；发送本地消息、手动回到底部或点击悬浮向下箭头恢复跟随。贴底时跟随回复与布局增长；用户拖动或上滚后保持阅读位置，加载更早历史也保持可见位置。是否贴底与是否跟随分别判断，离底超过 2 个布局单位且退出跟随时显示箭头；箭头位于输入框上方 12px，不占列表布局。只有点击箭头使用动画返回，其他跟随即时贴底。具体滚动与输入行为不因界面重构随意改变。

## 执行、停止与传输

输入、停止、维护、删除和内部报告经同一会话接纳线。普通输入在执行中以 steer 接纳，不强行中断模型或工具；停止撤回未应用输入并取消当前会话的普通执行，不取消独立后台工作。提交和停止按 requestId 去重，网络不确定时使用原 ID 核对；连接恢复不自动重发。

HTTP 提交与 SSE 观察分开。每次连接先接收快照再接收变化，不保存事件重放日志；关闭观察不停止执行。事件与错误处理见[会话事件](conversation-events.md)和[错误反馈](error-feedback.md)。

## 会话历史检索

`sessions_search` 与 `sessions_history` 只检索当前会话的可见历史，不检索内部输入、工具或附件正文；Posts 研究有受限的主会话读取范围。搜索以空格分隔字面关键词，匹配任一关键词即可；按不同关键词的命中数降序，同分按时间倒序。中文不自动分词，也不做同义词或向量检索。搜索直接扫描原生 entries，不建立正文副本或持久索引。

## 中断与恢复

启动先撤回遗留输入并取消不确定执行，仅继续回传已完成的后台结果；不重跑模型或工具，不回滚外部副作用。存储损坏与备份恢复见[存储说明](../operations/storage.md)。

## 验证边界

核心持久化、历史和恢复已在隔离环境检查；真实设备网络、前后台、键盘和长对话仍需验证。
