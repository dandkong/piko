# 错误反馈与恢复

错误显示在所属上下文，不建立全局执行状态副本。同一失败只设置一个主要反馈位置。

## 载体与位置

- 短暂操作反馈使用 `FeedbackToast`；列表和预览加载失败使用局部 `ErrorNotice`，已有内容保持可读，失败不伪装成空态。
- 聊天发送、停止、上传和读取错误留在聊天中；删除失败留在确认框，操作进行中禁止重复提交和关闭。
- 设置写入失败恢复上次确认的选择；响应丢失不证明服务端未保存，应重新读取核对。中断或执行失败的通用提示不自动重新执行工作。

## 聊天恢复边界

发送超时或结果不确定时保留 requestId，核对后仅以同一身份重试，不覆盖后续草稿；明确拒绝时恢复输入供编辑。停止失败重试原停止请求；上传保留成功附件，只补传未完成文件。SSE 重连和页面切换不重新提交输入或停止执行。本地未确认请求不是持久发件箱，应用重载后不保证恢复。

## 列表、预览与生成

刷新失败保留已有内容；换目录不展示旧目录内容，分页失败只重试对应游标。预览支持原地重新加载。Posts 生成结果不确定时复用原请求身份核对，确定结束后的重新生成使用新请求。

## 请求与错误协议

请求超时覆盖响应正文读取；具体超时以客户端 API 实现为准。`ApiError` 保留状态码和可选业务 code；未知错误使用友好提示，不据此推断未发生外部副作用。未认证代理或第三方错误不保证全面脱敏。

## 验证边界

主要恢复路径已用隔离脚本和模拟接口检查；原生设备、真实弱网、系统下载和读屏仍需验证。
