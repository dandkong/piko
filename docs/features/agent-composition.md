# Agent 构建与后台执行

内部 Agent 构建与后台驱动分离：调用方显式选择模型、cwd、指令、工具、历史起点和资源范围；共享执行层负责运行、取消和回传，不耦合保存任务业务。普通委派与任务行为分别见[后台工作](background-subagents.md)和[任务](tasks.md)。

## Agent 配置与历史起点

`server/runtime/agents/` 使用 Durable 原生 create/fork 和 AgentDoc。新会话可从空白开始或从指定 entry fork；fork 保留该点的历史，改变资源策略不会移除历史中已有内容。需要隔离上下文时使用空白会话。工具、角色和资源选择必须显式提供，不建立 Agent 配置副本。

## 动态资源策略

资源策略区分内建指导、工作区指导、记忆和技能索引；不发现祖先指导或个人 CLI 资源。当前范围：

| 会话 | 历史 | 自动资源 |
| --- | --- | --- |
| 主会话 / 旁聊 | 各自历史 | 全局指导、记忆和技能索引 |
| 普通后台工作 | 新建时空白，继续时复用 | 技能索引；不自动注入全局指导和记忆 |
| 保存任务执行 | 每次空白 | 任务记忆和技能索引 |
| 记忆整理 / Posts 研究 | 明确提供的输入 | 分别使用受限的文件或研究工具 |

资源选择是上下文策略，不是文件、网络或凭据沙箱；文件和命令仍按运行账户权限执行。

## 执行与回报

共享 Anchor/Reporter 使用原生任务、提交和回答身份完成执行与回报；内部报告通过父会话接纳线。普通委派可继续输入，保存任务使用固定指令；权限检查按 owner 与用途执行。Posts 和记忆整理使用各自的内部任务流程。

## 重启与角色模型

新后台工作使用当时的后台模型策略；未单独配置时跟随主模型。已有子会话保留自身 AgentDoc 和资源选择，不在重启时重新套用父模板。启动先取消不确定执行，只恢复已完成结果的回报，不重放模型或工具。

## 验证边界

资源范围、恢复和回报在隔离环境验证；真实模型、Telegram 网络与原生设备仍需验证。
