# Piko 产品约定

状态：产品方向已确定，后续能力尚未实现。当前实现进度以 [路线图](../ROADMAP.md) 为准。

## 定位与主体验

Piko 是本地优先的个人助理，帮助用户思考、规划，并逐步承担实际工作。它通过持续的主会话了解用户，保留工作成果和可复用的方法。前端覆盖 Web、iOS、Android，实际执行和工作区位于后端机器。

主会话是打开应用后的默认入口。用户不需要为了继续交流频繁新建、选择或切换聊天。应用重开或服务端重启后，应回到同一个主会话并保留历史。长期历史与模型当前上下文分别管理，模型压缩上下文不删除用户可见记录。

每个助理工作区拥有一个主会话。底层预留独立 side chat，用于专题研究；入口形式、历史可见性、记忆共享范围和研究结论回传尚待设计。当前不开放会话列表、会话切换或自动创建专题聊天。

## 助手的工作区

工作区是助理长期使用的文件夹，保存用户指导、记忆、技能、专题文件和产物。主会话和未来的 side chat 关联这个工作区；同属一个工作区不意味着每个会话自动读取所有文件或共享全部上下文。

用户能够理解、查看和修改这些内容。目前可以通过聊天要求助手维护文件、保存记忆、创建技能说明与脚本，并运行命令。助手必须以实际工具结果确认完成，不能仅用一条回复声称操作成功。自动记忆提取、检索及专门的技能管理界面尚未实现。

内建能力随 Piko 发布；用户内容持续保留，初始化和升级不能静默覆盖。工作区结构和 Pi 加载规则见 [架构约定](ARCHITECTURE.md)。

## 当前交互基线

- 保留近白背景、水豚头像、浅蓝/浅灰气泡和底部胶囊导航。头像与聊天列表叠加，列表起始留白避免遮住第一条消息。
- 回到最新消息使用悬浮圆形向下箭头，不占用列表布局；滚到底部包含保留的底部留白。
- 助手消息渲染 Markdown（标题、强调、列表、引用、代码、链接和表格），用户消息保留原文；代码块与宽表格可横向滚动。流式补全只用于显示，历史仍保存原始文本。图片暂显示说明文字，公式与代码语法高亮尚未实现。
- Web 的 Enter 发送、Shift+Enter 换行，中文选词确认不发送；原生输入框回车提交并保持焦点。暂不区分实体与屏幕键盘，后续根据使用反馈调整。
- 助手回复时可以停止；空白、连接中和回复中不能提交新消息。断线后恢复观察现有回复，不能误触发重复执行。
- 菜单、通知、附件和非 Chat 导航仍是禁用占位。功能真正可用后再启用。

## 功能演进

工作区、主会话持久化和 Pi 内建工具已接入，聊天能保存文件、使用与创建技能。下一步发展工具进度与 Activity / Artifacts、技能管理及访问边界，随后加入后台任务、Goals、Memory、通知、Ideas、Feed、Browser 和连接器。

主会话承担沟通；执行进度和产物可以有专门的查看入口。后续页面服务于真实能力，不为了填满导航提前制作假功能。

## 尚待设计

- side chat 怎样展开、返回主会话，以及结果和记忆如何共享。
- 记忆提取、修改、来源追踪、检索和遗忘的交互。
- 技能定制与升级冲突的展示，脚本执行与外部操作的授权方式。
- 长任务、Goals、主动建议和通知如何进入主会话而不过度打扰。
- 真机连接后端、登录和未来多用户部署的完整体验。

这些问题在对应功能方案中确定；当前不提前承诺界面或完整实现。
