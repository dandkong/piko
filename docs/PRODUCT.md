# Piko 产品约定

状态：产品方向已确定，后续能力尚未实现。当前实现进度以 [路线图](../ROADMAP.md) 为准。

## 定位与主体验

Piko 是本地优先的个人助理，帮助用户思考、规划，并逐步承担实际工作。它通过持续的主会话了解用户，保留工作成果和可复用的方法。前端覆盖 Web、iOS、Android，实际执行和工作区位于后端机器。

主会话是打开应用后的默认入口。用户不需要为了继续交流频繁新建、选择或切换聊天。应用重开或服务端重启后，回到同一个主会话并保留 Pi 已保存的历史。展示历史与模型当前上下文都来自 Pi 原生记录，投影规则不同；模型压缩上下文不删除用户可见记录。尚未由 Pi 保存的流式文字可能在服务端重启时丢失。

每个助理工作区拥有一个主会话。底层预留独立 side chat，用于专题研究；入口形式、历史可见性、记忆共享范围和研究结论回传尚待设计。当前不开放会话列表、会话切换或自动创建专题聊天。

## 助手的工作区

工作区是助理长期使用的文件夹，保存用户指导、记忆、技能、专题文件和产物。主会话和未来的 side chat 关联这个工作区；同属一个工作区不意味着每个会话自动读取所有文件或共享全部上下文。

用户能够理解、查看和修改这些内容。目前可以通过聊天要求助手维护文件、保存记忆、创建技能说明与脚本，并运行命令。助手必须以实际工具结果确认完成，不能仅用一条回复声称操作成功。自动记忆提取、检索及专门的技能管理界面尚未实现。

内建能力随 Piko 发布；用户内容持续保留，初始化和升级不能静默覆盖。工作区结构和 Pi 加载规则见 [架构约定](ARCHITECTURE.md)。

## 当前交互基线

- 保留近白背景、水豚头像、浅蓝/浅灰气泡和底部胶囊导航。对话列表铺满可用屏幕，头部、输入框与导航悬浮在列表上方；上下沿用同一套浅色渐隐样式，不增加覆盖整个头部的独立底板。头部渐隐覆盖实测头部内容并向下延伸 12px；底部渐隐覆盖输入框到屏幕底边的实测浮层区域，并在输入框上方延伸 32px。渐隐范围只负责视觉，与消息留白分开计算。列表顶部按头像/状态胶囊的实测底边加 13px 留白，底部按输入框实测顶边加同一 13px 留白；渐隐尺寸不参与滚动留白计算。滚动内容可经过浮层下面。
- 头像留在胶囊外；名字和状态保留上下排列，置于白底、浅边框的自适应胶囊内。正常空闲只显示名字，不保留状态行空位；思考、停止、连接和重连等状态显示在名字下方，胶囊自然增高、收缩。
- 一级导航固定为 Chat（主聊天）、Posts（助手主动发布的帖子）、Artifacts（产物）与 Tasks（事项），不建设 Ideas 模块；Chat 与 Tasks 可用，Posts / Artifacts 入口保持禁用。Tasks 使用单个事项保存 Prompt 与可选定时，结果由主 Agent 整理；界面只展示任务、上次结果和时间线，不提供管理表单。详见 [定时事项](features/scheduled-work-items.md)。
- 空会话保持聊天区域空白，不展示欢迎文案或快捷建议；历史加载期间保留加载提示。默认加载最近 50 条已保存消息，向上滚到顶部附近分批加载更早记录并保持阅读位置；顶端提供手动加载及失败重试入口。实时快照不清除已加载的连续历史；长时间断线导致最新窗口与本地无交集时回到最新页，避免跳过中间记录。
- 回到最新消息使用悬浮圆形向下箭头，不占用列表布局；按钮停在输入框上方 12px，末条消息与输入框保持统一的 13px 间距。
- 助手消息渲染 Markdown（标题、强调、列表、引用、代码、链接和表格），用户消息保留原文；代码块与宽表格可横向滚动。流式补全只用于显示，历史仍保存原始文本。图片暂显示说明文字，公式与代码语法高亮尚未实现。
- Web 的 Enter 发送、Shift+Enter 换行，中文选词确认不发送；原生输入框回车提交并保持焦点。暂不区分实体与屏幕键盘，后续根据使用反馈调整。
- 助手回复期间仍可发送补充或纠正，RN/TG 统一采用 steer all；在原生接纳边界把已积累的输入一起加入正在执行的工作。输入框有草稿时显示发送，回复中且草稿为空时显示停止。空白、初始化连接中、输入尚未确认接纳或正在停止时不能提交。断线后恢复观察现有回复，不能误触发重复执行。
- 左上菜单与右上设置按钮均为浅边框圆形样式，目前不接入点击行为、保持禁用占位；附件和 Posts / Artifacts 导航也保持禁用。

用户消息与助手回复各自展示，不要求一一对应，也不因 steer 合并或重发已完成回复。只有正在生成的同一条助手消息随流式内容更新。

steer 接纳不会强行中断已开始的模型请求或工具。停止撤回尚未应用的补充输入；这些输入不再作为用户消息进入原生历史。实现与设备验证范围见 [路线图](../ROADMAP.md#运行中输入steer-all已实现)。

## 功能演进

已接入 RN 与可选 Telegram 两个入口，RN 保留完整产品体验，TG 按平台适合的能力逐步接入，不要求功能对齐。两端共用主会话，TG 支持私聊文本、回复、停止与只读查询，以及空闲时的模型/思考强度按钮选择和上下文压缩；状态展示当前模型、思考强度和直接可得的运行时信息。附件、群聊、后台通知和复杂交互另行讨论。RN 展示共享历史并在前台同步；RN 回复默认不自动发送到 TG，可在 TG 查询最近历史。通道提示与命令结果分别展示，不进入模型对话。详见 [双通道说明](features/telegram-channel.md)，真实 Bot 与设备行为尚待验证。

工作区、主会话持久化、Pi 内建工具和 Telegram 文本通道已接入，聊天能保存文件、使用与创建技能。界面围绕 Posts、Artifacts 与 Tasks 三个模块发展：主动内容归 Posts，文件和结构化成果归 Artifacts，任务进度与调度归 Tasks。Tasks 首版支持手动、一次性和周期事项，结果同普通子 Agent 回传主 Agent 整理；界面只读展示任务、上次结果和时间线，并提供最少的干预操作，产物文件留给助手使用，全局 Artifacts 模块尚未建设。技能、记忆、通知、浏览器和连接器按实际能力接入，不为它们提前增加独立一级导航。

主会话承担沟通；执行进度和产物可以有专门的查看入口。后续页面服务于真实能力，不为了填满导航提前制作假功能。

## 尚待设计

- side chat 怎样展开、返回主会话，以及结果和记忆如何共享。
- 记忆提取、修改、来源追踪、检索和遗忘的交互。
- 技能定制与升级冲突的展示，脚本执行与外部操作的授权方式。
- 长任务、主动帖子和通知如何与主会话配合而不过度打扰。
- 真机连接后端、登录和未来多用户部署的完整体验。

这些问题在对应功能方案中确定；当前不提前承诺界面或完整实现。
