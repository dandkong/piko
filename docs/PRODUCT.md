# Piko 产品范围与交互基线

本文记录 Piko 的产品目标、当前交互基线和明确边界。具体实现状态与未实现能力见[路线图](../ROADMAP.md)及各项[功能说明](README.md#功能说明)。

## 定位与主体验

Piko 是本地优先的个人助理，帮助用户思考、规划，并逐步承担实际工作。它通过持续的主会话了解用户，保留工作成果和可复用的方法。前端覆盖 Web、iOS、Android，实际执行和工作区位于后端机器。

主会话是打开应用后的默认入口。用户不需要为了继续交流频繁新建、选择或切换聊天。应用重开或服务端重启后，回到同一个主会话并保留 Pi 已保存的历史。展示历史与模型当前上下文都来自 Pi 原生记录，投影规则不同；模型压缩上下文不删除用户可见记录。尚未由 Pi 保存的流式文字可能在服务端重启时丢失。

每个助手工作区拥有一个默认主会话，并支持用户从抽屉新建独立旁聊。旁聊有独立历史和停止；一键使用默认名“新旁聊”创建并直接进入，列表右侧三点菜单提供重命名和删除。删除需确认且不可恢复，不提供归档或恢复入口；顶部头像名字固定 Piko。旁聊共享工作区记忆、技能和通用工具，但不继承主会话聊天记录、不自动回传主会话、不提取旁聊记忆，也不提供任务管理工具；可以委派后台工作，结果只回到发起它的旁聊。Chat 导航返回主会话，应用重开默认主会话。见[旁聊说明](features/side-chats.md)。

## 任务、后台工作与执行

- **任务**：保存下来、可手动或定时运行的工作指令，有自己的目录和记忆；技术类型为 `AssistantTask`，不是待办勾选项。
- **后台工作**：直接交给 Piko 在后台处理的工作，可继续补充指令；用户不需要理解子 Agent，代码与工具保留 `subagent` 名称。
- **执行记录／运行结果**：某项任务实际运行一次后留下的记录与回答，不等于任务本身。
- **进行中／已归档**：任务的生命周期。归档停止未来调度并保留历史；恢复重新启用未来调度，不立即运行。归档不代表执行完成；单次执行成功才称“已完成”。

## 助手的工作区

工作区是助理长期使用的文件夹，保存用户指导、记忆、技能、专题文件和产物。主会话和旁聊关联这个工作区；同属一个工作区不意味着每个会话自动读取所有文件或共享全部上下文。

工作区是后端机器上的普通目录。用户可以直接在该机器查看和修改文件，也可以通过聊天要求助手维护文件、保存记忆、创建技能说明与脚本并运行命令。主会话闲置 30 分钟后，后台记忆整理会使用 `read`、`write`、`edit` 维护每日与长期记忆；它只由后台闲置调度触发，没有专用手动触发工具。助手必须根据实际工具结果确认文件修改，不能仅凭回复声称完成。专门的记忆浏览/检索和技能管理界面尚未实现。

内建能力随 Piko 发布；用户内容持续保留，初始化和升级不能静默覆盖。工作区结构和 Pi 加载规则见 [架构约定](ARCHITECTURE.md)。

## 当前交互基线

交互控件的统一状态、尺寸、颜色和动效见 [交互与视觉规范](INTERACTION.md)。

- 保留近白背景、水豚头像、浅蓝/浅灰气泡和底部胶囊导航。对话列表铺满可用屏幕，头部、输入框与导航悬浮在列表上方；上下沿用同一套浅色渐隐样式，不增加覆盖整个头部的独立底板。头部渐隐覆盖实测头部内容并向下延伸 12px；底部渐隐覆盖输入框到屏幕底边的实测浮层区域，并在输入框上方延伸 32px。渐隐范围只负责视觉，与消息留白分开计算。列表顶部按头像/状态胶囊的实测底边加 13px 留白，底部按输入框实测顶边加同一 13px 留白；渐隐尺寸不参与滚动留白计算。滚动内容可经过浮层下面。
- 头像留在胶囊外；名字和状态保留上下排列，置于白底、浅边框的自适应胶囊内。正常空闲只显示名字，不保留状态行空位；思考、停止、连接和重连等状态显示在名字下方，胶囊自然增高、收缩。
- 一级导航固定为 Chat（主聊天）、Tasks（任务）、Posts（助手主动发布的帖子）与 Artifacts（产物），不建设 Ideas 模块；四个页签均已启用；Posts 目前只有空状态，没有发布数据源，不展示模拟帖子；Artifacts 浏览工作区 `artifacts/` 文件夹，支持面包屑、Markdown/常见文本预览，以及列表菜单中的下载和确认删除；任务执行目录暂不聚合。详情见[产物浏览](features/artifacts.md)。除 Chat 外，各页签共用同一套列表/详情节奏。Tasks 使用单个任务保存 Prompt 与可选定时，结果由主 Agent 整理；界面按进行中/已归档分组展示任务和已结束执行的时间线，图标操作归档/恢复，不提供管理表单；列表不显示执行状态或结果，运行中的执行不进入时间线。详见 [任务与执行记录](features/tasks.md)。
- 空会话保持聊天区域空白，不展示欢迎文案或快捷建议；历史加载期间保留加载提示。默认加载最近 50 条已保存消息，向上滚到顶部附近分批加载更早记录并保持阅读位置；顶端提供手动加载及失败重试入口。实时快照不清除已加载的连续历史；长时间断线导致最新窗口与本地无交集时回到最新页，避免跳过中间记录。
- 刷新或切回会话后从最新消息开始；发送新消息恢复贴底，贴底时随流式正文和等待提示的布局增长自动跟随。用户上滚或拖动后保持阅读位置，手动滚回底部或点击“最新消息”恢复跟随。回到最新消息使用悬浮圆形向下箭头，实际贴底时隐藏，不占用列表布局；按钮停在输入框上方 12px，末条消息与输入框保持统一的 13px 间距。
- 助手消息渲染 Markdown（标题、强调、列表、引用、代码、链接和表格），用户消息保留原文；代码块与宽表格可横向滚动。流式补全只用于显示，历史仍保存原始文本。图片暂显示说明文字，公式与代码语法高亮尚未实现。
- Web 的 Enter 发送、Shift+Enter 换行，中文选词确认不发送；原生输入框回车提交并保持焦点。暂不区分实体与屏幕键盘，后续根据使用反馈调整。
- 助手回复期间仍可发送补充或纠正，RN/TG 统一采用 steer all；在原生接纳边界把已积累的输入一起加入正在执行的工作。输入框有草稿时显示发送，回复中且草稿为空时显示停止。空白、初始化连接中、输入尚未确认接纳或正在停止时不能提交。断线后恢复观察现有回复，不能误触发重复执行。
- 左上菜单打开层叠式导航抽屉：导航和旁聊列表铺在全高底层，使用略深冷灰底色和细分界线，不作为悬浮卡片；主界面仅向右平移覆盖其上，不缩放、不添加动态阴影或圆角裁切；不重排或压缩聊天布局，点击露出的主界面可关闭。抽屉复用底部四个页签；旁聊列表每行右侧的三点菜单提供重命名与删除。删除需确认且不可恢复，成功后停止并清理该旁聊及其后台工作；不提供归档或恢复入口。点击页签或旁聊后抽屉随主界面归位。右上不再放设置按钮；抽屉左下角设置直接显示主/后台模型下拉选择及思考强度，不展示其他配置；供应商、目录、凭据、工具、通道与环境变量均由部署管理。用户只设置一个统一主模型，右下角一键以默认名“新旁聊”创建并直接进入；模型设置 API 未鉴权且仅能更改模型策略，详见[设置与模型](features/settings.md)。

用户消息与助手回复各自展示，不要求一一对应，也不因 steer 合并或重发已完成回复。只有正在生成的同一条助手消息随流式内容更新。

steer 接纳不会强行中断已开始的模型请求或工具。停止会撤回尚未应用的补充输入；这些输入不会作为用户消息进入原生历史。实现边界见[工作区与主会话说明](features/workspace-and-main-chat.md#执行停止与传输)。

## 功能演进

已接入 RN 与可选 Telegram 两个入口，RN 提供主要产品体验，TG 按平台特性提供相应能力，不要求功能完全对齐。两端共用主会话；TG 支持私聊文本、流式回复、停止、状态与历史查询、模型/思考强度选择、上下文压缩，以及只读浏览后台工作和任务。Telegram 图片可作为附件进入工作区工具流程；群聊、语音、系统推送和可靠补发尚未接入。RN 展示共享历史并在前台同步；主会话的助手回复不按输入来源区分，Web/App 与 Telegram 发起的主会话输出都会投递到 Telegram；App 用户输入本身不回显到 Telegram。工具进度仍按 Telegram 通道的表现呈现。通道提示与命令结果不进入模型对话。详见[双通道说明](features/telegram-channel.md)，真实 Bot 网络行为仍需验证。

工作区、主会话持久化、内建文件/命令工具、网页工具和 Telegram 私聊已接入；助手可以维护工作区文件、记忆和技能。一级模块为 Tasks、Posts 与 Artifacts：Tasks 已支持手动、一次性和周期任务，页面展示任务与已结束的执行记录，并提供归档/恢复；Posts 目前只有空状态；Artifacts 已提供工作区产物浏览、Markdown/文本预览、下载和确认删除；任务执行目录聚合、创建/重命名/移动及 PDF/Office 内置预览尚未实现。记忆/技能管理界面、通知、浏览器自动化和外部连接器也尚未实现。能力成熟并有真实数据后再扩展页面，不以模拟内容填充空状态。

主会话承担沟通；执行进度和产物可以有专门的查看入口。后续页面服务于真实能力，不为了填满导航提前制作假功能。

## 尚待设计

- 旁聊不继承主会话上下文，不自动回传主会话或提取记忆；可以委派后台工作，但子 Agent、状态与结果都限定在发起旁聊。删除旁聊时会停止并清理它拥有的后台工作；不提供旁聊归档/恢复。
- 记忆的专门浏览/版本管理、用户校正与遗忘交互；后台每日/长期整理已实现，按需搜索仍使用工作区文件工具。
- 技能定制与升级冲突的展示，脚本执行与外部操作的授权方式。
- 长任务、主动帖子和通知如何与主会话配合而不过度打扰。
- 真机连接后端、登录和未来多用户部署的完整体验。

这些问题在对应功能方案中确定；当前不提前承诺界面或完整实现。
